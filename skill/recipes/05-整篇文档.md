# 05 整篇文档：自荐信、动机信、个人陈述

有时用户要的不是某段经历的一句写法，而是**一整篇**文档。它在经历库里叫「申请记录」。

**为什么整篇存、不拆成段落：** 一段话离开整封信的上下文就不好复用了。所以整篇存成一个文件，每段标记它用到了哪段经历；前端会在那段经历的卡片下显示这一段，点开能跳到全文。

---

## 第 1 步：弄清要求

和 04 第 1 步一样：申请什么、文档类型（自荐信 / 动机信 / Cover letter / 个人陈述）、字数、语言。

## 第 2 步：找经历，列给用户确认

按 04 第 2、3 步做：列出所有可能相关的经历，问用户「这封信打算用这几段经历，可以吗？」

## 第 3 步：写全文

- 开头一段（称呼 + 为什么申请），中间每段讲一段经历，结尾一段（期待 + 致谢）。
- 每个中间段落只围绕**一段**经历，这样能准确标记来源。
- 只用卡片里的事实和数字，不编造。
- 发给用户看，按意见修改，直到用户满意。

## 第 4 步：存成申请记录（用户确认后）

起 id：`<文档类型拼音缩写>-<申请对象缩写>-<年月>`，如 `zjx-zhijiao-202611`（自荐信·支教）。检查重名：

```bash
test -e "<VAULT>/applications/<id>.json" && echo TAKEN || echo FREE
```

写到 `<VAULT>/applications/<id>.json`：

```json
{
  "schema": 1,
  "id": "<id>",
  "title": "<申请对象 · 文档类型，如 某乡村支教志愿项目 · 自荐信>",
  "kind": "<自荐信/动机信/Cover letter/个人陈述>",
  "target": "<申请对象>",
  "scene": "<场景：志愿项目/实习申请/奖学金/升学/……>",
  "date": "<年.月，如 2026.11>",
  "lang": "<中文/English>",
  "paras": [
    {"text": "<第 1 段全文>", "card": null},
    {"text": "<第 2 段全文>", "card": "<这段用到的经历 id>"},
    {"text": "<最后一段>", "card": null}
  ],
  "created": "<当前时间>",
  "updated": "<当前时间>"
}
```

- 每个段落一项，按顺序。`card` 填这段用到的经历 id（必须是 `experiences/` 里真实存在的文件名，不带 `.json`）；开头、结尾这种没用到经历的段落填 `null`（不加引号）。
- 段落文字里不要有换行；需要分段就拆成两项。
- 当前时间的命令见 02-入库.md 第 4 步。

校验：

```bash
python3 -m json.tool "<VAULT>/applications/<id>.json" > /dev/null && echo OK
```

再检查每个 `card` 都真实存在：

```bash
python3 - "<VAULT>" "<id>" <<'EOF'
import json, os, sys
v, i = sys.argv[1], sys.argv[2]
d = json.load(open(os.path.join(v, "applications", i + ".json"), encoding="utf-8"))
bad = [p["card"] for p in d["paras"] if p.get("card") and not os.path.exists(os.path.join(v, "experiences", p["card"] + ".json"))]
print("MISSING CARDS:", bad) if bad else print("CARDS OK")
EOF
```

有 `MISSING CARDS` 就把错的 id 改对（或改成 `null`）。

## 第 5 步：告诉用户

「自荐信已存为申请记录。右半屏左栏「申请记录」里能看到全文；用到的 3 段经历卡片下也会出现对应段落。需要 PDF 的话说一声。」（导出见 `recipes/07-导出PDF.md`）
