# 08 检查作品快捷方式

> **快捷路径（推荐）：** 直接用 `works.py` 一键盘点或基于 Spotlight + `sha256` / `size` 自动找回并重绑软链接：
> - 仅盘点（只读）：`python3 "<SKILL>/scripts/works.py" audit "<VAULT>"`
> - 先预演找回结果（只读）：`python3 "<SKILL>/scripts/works.py" relink "<VAULT>" --dry-run`
> - 确认无误后自动修复并更新卡片 `updated`：`python3 "<SKILL>/scripts/works.py" relink "<VAULT>"`

下面是手动排查与修复原理（若上面无法自动匹配到唯一文件时对照处理）：

作品是用快捷方式（软链接）挂在经历下的，原文件还在用户原来的位置。用户把原文件移走、改名或删除后，快捷方式就断了，前端会显示「原文件找不到了」。

---

## 第 1 步：找出所有断掉或变了的快捷方式

复制运行（只读，不改任何东西）：

```bash
python3 - "<VAULT>" <<'EOF'
import json, glob, os, sys
bad = 0
for f in sorted(glob.glob(os.path.join(sys.argv[1], "experiences", "*.json"))):
    c = json.load(open(f, encoding="utf-8"))
    for w in c.get("works", []):
        if not isinstance(w, dict) or not w.get("original"):
            continue
        o = w["original"]
        if not os.path.exists(o):
            bad += 1; print("MISSING", c["id"], "|", w.get("label"), "|", o)
        elif w.get("size") is not None and os.path.isfile(o) and os.path.getsize(o) != w["size"]:
            bad += 1; print("CHANGED", c["id"], "|", w.get("label"), "|", o)
print("ALL_OK" if bad == 0 else f"{bad} problem(s)")
EOF
```

- `ALL_OK`：都没问题，告诉用户即可。
- `MISSING`：原文件不在原位置了，做第 2 步。
- `CHANGED`：文件还在，但内容被改过（大小变了）。一般没关系；问用户要不要更新记录（第 4 步只更新 `size` 和 `mtime`）。

## 第 2 步：找文件的新位置

用文件名搜（把 `<文件名>` 换成 `original` 路径的最后一段）：

- macOS：
  ```bash
  mdfind -name "<文件名>" | head -10
  ```
- 其他系统：
  ```bash
  find "$HOME" -name "<文件名>" -not -path "*/.Trash/*" 2>/dev/null | head -10
  ```

## 第 3 步：问用户

- 找到了：「『<label>』原来在 <旧路径>，现在好像在 <新路径>，要改成指向新位置吗？」
- 没找到：「找不到『<label>』了，可能被删掉了。要从这段经历里移除它，还是你告诉我新位置？」

## 第 4 步：修复（用户确认后）

**指向新位置：**

```bash
ln -sfn "<新路径>" "<VAULT>/assets/<asset 字段的值>" && echo RELINKED
```

然后用 03-挂作品.md 第 1 步的命令拿到新路径的 `size`、`mtime`，在卡片 JSON 里更新这一项的 `original`、`size`、`mtime`，更新 `updated`，校验。

**移除这个作品：** 从卡片 `works` 数组里删掉这一项，再把快捷方式移到回收站：

```bash
mkdir -p "<VAULT>/.trash" && mv "<VAULT>/assets/<asset 字段的值>" "<VAULT>/.trash/" && echo MOVED
```

更新 `updated`，校验 JSON。
