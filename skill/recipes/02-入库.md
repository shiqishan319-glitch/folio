# 02 入库：把素材变成经历卡片

用户会给你各种素材：一段口述、备忘录、面试准备文档。（**一整份旧简历**走 `recipes/11-导入旧简历.md`：它会同时填个人信息、存一份原样的简历。）你的任务是把它们拆成一张张「经历卡片」，每张存成一个 JSON 文件。

**素材是什么格式都行，用你自己的能力读：** 截图、照片、扫描件、聊天记录导出、语音转的文字、网页……你的工具能直接看图、读文件，就直接读。读不了的（比如看不了图片），请用户把文字粘贴过来。要求只有一条：卡片里的每个事实和数字都要能在素材里找到。

**为什么一段经历只存一张卡：** 以后同一段经历会有很多种写法（简历版、网申版、英文版）。它们都挂在这一张卡下，用户才找得到、比得了。所以入库前一定要先查重。

---

## 第 1 步：看看库里已经有什么

```bash
ls "<VAULT>/experiences/"
```

再用素材里的关键词（公司名、项目名）查一下有没有同一段经历：

```bash
grep -l "<关键词>" "<VAULT>/experiences/"*.json
```

- 有输出（文件名）：这段经历**已经存在**，读那个文件，把新信息合并进去（见第 6 步），不要新建。
- 没输出：新建卡片。

## 第 2 步：拆分

一张卡 = 一段**有时间、有身份**的经历，比如一次实习、一个项目、一个奖项、一次志愿服务、一篇反思。

- 一份简历里有 3 段实习 → 3 张卡。
- 「我在 A 公司实习时做了两个项目」→ 通常 1 张卡（实习），两个项目写进 `fact` 里。除非用户说要分开。
- 不确定怎么拆，问用户一句。

选类型（`type`），只能用 `<VAULT>/config.json` 里 `types` 列出的值（默认是下面五个）：

| type | 什么时候用 |
|---|---|
| `实习` | 实习、兼职、工作 |
| `项目` | 课程项目、比赛、自己做的作品、活动策划、科研 |
| `志愿者` | 志愿服务、公益活动 |
| `获奖` | 奖学金、荣誉称号、比赛名次 |
| `技能` | **技能与语言、所在城市 / 到岗时间**（同样用卡片管理，天然支持 `v1 通用` / `v2 偏技术` / `v3 英文` 等多版本写法） |
| `思考` | 反思、复盘、心得（没有具体成果也可以记） |

## 第 3 步：起 id

规则：`<机构或项目的英文/拼音缩写>-<开始年份>`，全小写，只用字母、数字和 `-`。

- 小红书 2025 年的实习 → `xhs-2025`
- 校园公益市集 2024 → `gongyi-shiji-2024`

检查有没有重名：

```bash
test -e "<VAULT>/experiences/<id>.json" && echo TAKEN || echo FREE
```

输出 `TAKEN` 就在后面加 `-2`、`-3`。

## 第 4 步：拿当前时间

```bash
python3 -c "import datetime;print(datetime.datetime.now().astimezone().isoformat(timespec='seconds'))"
```

输出类似 `2026-11-16T16:50:00+08:00`，填到 `created` 和 `updated`。

## 第 5 步：写文件

文件路径：`<VAULT>/experiences/<id>.json`。用你的写文件工具写入下面的模板，把每个 `<...>` 换成真实内容。**素材里没有的信息填 `""`，不要编。**

```json
{
  "schema": 1,
  "id": "<id>",
  "type": "<实习/项目/志愿者/获奖/思考>",
  "org": "<机构名，如 小红书>",
  "title": "<机构 · 做了什么，如 小红书 · 内容运营实习>",
  "time": "<开始 – 结束，如 2025.06 – 2025.09；只有一个时间点就写 2025.05>",
  "year": <开始年份数字，如 2025>,
  "role": "<身份，如 运营实习生>",
  "tags": ["<标签1>", "<标签2>"],
  "fact": "<事实：做了什么，1–3 句>",
  "result": "<结果：带来了什么，尽量有数字>",
  "thought": "<思考：学到了什么、当时怎么想的>",
  "works": [],
  "writings": [],
  "created": "<第 4 步的时间>",
  "updated": "<第 4 步的时间>"
}
```

几个容易写错的地方：
- `year` 是数字，**不加引号**：`"year": 2025`。
- `time` 中间的连接符用 `–`（短横线两边各一个空格）。
- 字符串里不要用中文引号 `“”` 当 JSON 的引号；内容里需要引号时用 `「」`。
- 最后一个字段后面**没有逗号**。
- `tags` 2–4 个，用短词：`实习相关`、`AI 产品`、`数据分析`、`活动策划`、`公益`、`公共表达`……先看看库里已有卡片用过哪些标签，尽量复用（同一个意思别造两个词）。

如果素材里已经有现成的简历句子，可以顺手放进 `writings`：

```json
"writings": [
  {"type": "简历条目", "versions": [{"name": "v1 原简历", "text": "<原句>"}]}
]
```

**完整例子**（用户说：「我去年暑假在小红书做内容运营实习，负责一个垂类话题的选题和数据复盘，后来话题互动量涨了 30% 左右」）：

```json
{
  "schema": 1,
  "id": "xhs-2025",
  "type": "实习",
  "org": "小红书",
  "title": "小红书 · 内容运营实习",
  "time": "2025.07 – 2025.08",
  "year": 2025,
  "role": "内容运营实习生",
  "tags": ["实习相关", "内容", "数据分析"],
  "fact": "负责一个垂类话题的选题与数据复盘。",
  "result": "话题互动量提升约 30%。",
  "thought": "",
  "works": [],
  "writings": [],
  "created": "2026-11-16T16:50:00+08:00",
  "updated": "2026-11-16T16:50:00+08:00"
}
```

（「去年暑假」按当前年份推算成 2025.07 – 2025.08；推算出来的日期要在第 7 步跟用户确认。）

## 第 6 步：校验

```bash
python3 -m json.tool "<VAULT>/experiences/<id>.json" > /dev/null && echo OK
```

没有 `OK`：读报错里的行号，打开文件修好那一行，再校验。常见原因见 `recipes/09-踩坑与解决.md`。

**合并到已有卡片时：** 先读整个文件，在原内容上补充或修改字段（不要删掉原来的 `writings` 和 `works`），把 `updated` 换成新时间，整个文件写回，再校验。

## 第 7 步：追问（让卡片更有价值）

**为什么要追问：** 事后最难补的就是数字、难点和当时的想法；用户这会儿还记得，过几个月就忘了。但追问只是建议，用户不想答就算了。

检查刚写的卡片，按下面的顺序挑**最多 3 个**问题，一次问完：

| 缺什么 | 可以这样问 |
|---|---|
| `result` 空，或没有数字 | 「这件事最后有什么结果？有没有具体数字，比如人数、增长、金额、排名？」 |
| `thought` 空 | 「做这件事时，你遇到最难的一点是什么？现在回头看学到了什么？」 |
| `time` 是推算的或空 | 「大概是哪年哪月到哪年哪月？」 |
| `role` 空 | 「你在里面是什么角色？」 |
| 有作品但没挂 | 「有没有相关的文件（PPT、照片、视频、链接）？告诉我路径，我挂上快捷方式。」 |

用户回答后，把答案写进对应字段，更新 `updated`，再校验一次。用户说「跳过」就保持原样。

## 第 8 步：告诉用户

例：「已入库 3 段经历：小红书实习、校园公益市集、社区博物馆讲解。右半屏时间线里已经能看到。还有两个小问题想确认……」

## 补充：从代码仓库或长文档自动起草卡片

当用户直接丢给你一个**本地项目文件夹、GitHub 链接或长文档**时：

1. **提取事实（用你自身的文件/联网能力）**：只读 `README`、核心入口文件或 `git log`（或长文档的目录与摘要），提炼项目定位、技术栈、核心功能与真实可验证的成果；**文档里没写的数字与角色不要编，留空 `""`**。
2. **按第 1～6 步起草并校验卡片**：默认 `type` 为 `"项目"`，把仓库链接或文档路径顺手记入 `works`（本地文件用软链接规则，网址直接写 `{"kind": "link", "label": "项目仓库", "url": "..."}`）。
3. **按第 7 步追问补全**：起草后优先追问用户在项目里的**具体角色分工**、**遇到的核心难点**和**实际效果/量化结果**（最多 3 个问题）。

## 补充：作品集（works）分层存储与语义索引

遇到 PPT、图片、视频、PDF 等多模态异构资料时，遵循 **「体积不爆炸 + 极好找」** 的三层存储策略：

1. **Tier 0（纯链接，`kind: "link"`）**：飞书/Notion/GitHub/Figma/B 站演示等在线内容，只记 `url`，0 体积。
2. **Tier 1（内收，`mode: "copy"`）**：**≤ 5 MB** 的图片、获奖证书、核心一页纸 PDF 等轻文件，直接复制进 `<VAULT>/assets/<id>/`，换电脑或同步时永不丢失。
3. **Tier 2（外置，`mode: "link"` + `summary`）**：**> 5 MB** 的大文件、视频、大型 `.pptx`、压缩包或文件夹，原文件留在原处，在 `assets/<id>/` 放软链接，**并必须顺手写 1–3 句 `summary` 纯文本摘要**（提炼核心页面、关键数据、画面内容），让前端搜索和后续 AI 写简历不用打开大文件就能秒级命中。

推荐直接调用辅助脚本自动完成分流、计算 `sha256` 指纹并写入卡片：

```bash
python3 "<SKILL>/scripts/works.py" attach "<VAULT>" "<id>" "<原文件路径>" --summary "<1-3句内容摘要>"
```

若原文件日后被用户移动或改名导致前端提示「原文件找不到了」，运行自动找回并修复软链接：

```bash
python3 "<SKILL>/scripts/works.py" relink "<VAULT>"
```
