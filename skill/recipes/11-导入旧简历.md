# 11 导入旧简历：一份简历 → 个人信息 + 一张张经历卡片 + 一份原样的简历

用户说「这是我的简历」「帮我把旧简历导进来」，或者发来一个简历文件（PDF、Word、截图）时，读这个文件。这通常是新用户第一次用经历库。

**做完以后用户会得到三样东西：**
1. 个人信息填好了（姓名、联系方式、教育背景）；
2. 简历里的每一段经历都变成了一张卡片，原文一字不改地存成这张卡片的「v1 原简历」版本；
3. 一份和原简历一样的简历记录（`resumes/`），右半屏马上就能看到、能直接改。

**为什么原文一字不改：** 用户要能放心——导进来的就是自己写的。改写、润色是以后按岗位做简历时的事（`recipes/10-按岗位做简历.md`），新写法存成新版本，原文一直留着。

---

## 第 1 步：读出简历全文

**先直接读文件。** 大多数 AI 工具能直接读 PDF、Word 和图片（截图）。读到全文就跳到第 2 步。

读不了时，按文件类型用命令：

Word（`.docx`，Python 标准库就能读）：

```bash
python3 - "<简历文件路径>" <<'EOF'
import re, sys, zipfile
xml = zipfile.ZipFile(sys.argv[1]).read("word/document.xml").decode("utf-8")
for para in re.findall(r"<w:p[ >].*?</w:p>", xml, re.S):
    text = "".join(re.findall(r"<w:t[^>]*>(.*?)</w:t>", para))
    if text.strip():
        print(text)
EOF
```

PDF：

```bash
pdftotext -layout "<简历文件路径>" - 2>/dev/null || echo NO_PDFTOTEXT
```

- 打印出了文字：继续。
- 输出 `NO_PDFTOTEXT`：请用户把简历另存为 Word，或直接把文字粘贴过来。
- 输出几乎是空的：这是扫描件（PDF 里全是图片）。你能看图就把每页当图片读；不能就请用户发 Word 或粘贴文字。

读出来以后，先对一下：姓名、每段经历的机构和时间都读全了没有。PDF 两栏排版时，左右两栏的字可能交错在一起，要按意思重新理顺；拿不准的地方，第 7 步问用户。

## 第 2 步：个人信息 → `config.json`

先读 `<VAULT>/config.json`。把简历里的这些信息填进 `profile`：

| 简历里的 | 写到 |
|---|---|
| 姓名 | `name` |
| 求职意向（如「求职意向：内容运营实习」） | `headline` |
| 所在城市、到岗时间 | `location` |
| 电话、邮箱 | `phone`、`email` |
| 个人主页、作品集链接 | `links`（数组） |
| 每段教育：学校、专业、学历、时间 | `education` 数组里的一项：`school`、`major`、`degree`、`time` |
| 教育下面的 GPA、主修课程、荣誉 | 同一项的 `details`，**一行一条，原样保留**，如 `"GPA：3.72 / 4.0（专业前 15%）"` |

规则：
- `profile` 里**已经有值的字段不要覆盖**。简历里的和已有的不一样时，留着已有的，第 7 步问用户用哪个。
- 时间统一写成 `2021.09 – 2025.06`（年.月，短横线两边各一个空格）。简历写「2021年9月 - 2025年6月」就转成这个格式；「至今」照写：`2024.01 – 至今`。
- 写回后校验：`python3 -m json.tool "<VAULT>/config.json" > /dev/null && echo OK`

## 第 3 步：拆成经历卡片

简历里每一个「有机构、有身份、有时间」的条目，就是一张卡片。按所在的分节定类型：

| 简历里的分节 | `type` |
|---|---|
| 实习经历、工作经历 | `实习` |
| 项目经历、科研经历、比赛、作品 | `项目` |
| 志愿经历、社会实践、学生工作 | `志愿者` |
| 荣誉奖项（单独成节时，每个奖一张卡） | `获奖` |
| 技能、语言、个人总结 | `技能`（整节一张卡，标题如「技能与语言」） |

教育背景里的荣誉（如「所获荣誉：……」）已经在第 2 步存进 `details` 了，不用再拆成卡片。

**先查重。** 库里可能已经有同一段经历（老用户再导一份新简历时）：

```bash
grep -l "<机构名>" "<VAULT>/experiences/"*.json
```

有输出就读那张卡片，**不要新建**，把这次的原文作为一个新版本加进它的「简历条目」（版本名 `v<序号> 原简历 <年月>`），其他字段只补空着的。

**新建卡片**，按 `recipes/02-入库.md` 第 3～5 步起 id、拿时间、写文件，字段这样填：

| 字段 | 填什么 |
|---|---|
| `org` / `role` | 机构、身份，如 `字节跳动` / `用户增长运营实习生` |
| `title` | `机构 · 身份`，如 `字节跳动 · 用户增长运营实习生`（技能卡写 `技能与语言`） |
| `time`、`year` | 统一格式的时间，`year` 是开始年份数字 |
| `fact` | 做了什么：1–2 句，**用原文的话**概括 |
| `result` | 结果：把原文里带数字的结果**原样摘出来**，没有就 `""` |
| `thought` | `""`（简历里一般没有，第 7 步问） |
| `tags` | 2–3 个短词，先看库里已有的标签 |
| `writings` | 原文，见下 |

原文放进 `writings`，**一字不改**：

```json
"writings": [
  {"type": "简历条目", "versions": [
    {"name": "v1 原简历", "text": "围绕「新用户 7 日留存」目标，负责拉新活动与新手引导优化。\n活动策划：策划并上线 3 个校园拉新活动，累计带来新增注册 15 万。\n新手引导：拆解注册到首次发布的漏斗，推动引导页改版，7 日留存提升 23%。"}
  ]}
]
```

- 原简历里每个要点一行，行之间用 `\n`；去掉行首的圆点 `•`。
- 要点原本有小标题（「活动策划：……」）就原样保留，导出时小标题会加粗。
- 要点前面那句不带圆点的概述，放在第一行。

**不编造任何数字和细节。** `fact`、`result` 里出现的每个数字，都必须能在原简历里找到。

每写完一张卡片就校验：

```bash
python3 -m json.tool "<VAULT>/experiences/<id>.json" > /dev/null && echo OK
```

## 第 4 步：存一份原样的简历

把原简历本身也存成一份简历记录，分节和顺序都照原简历：

起 id：`jl-yuan-<年月>`，如 `jl-yuan-202611`；重名就加 `-2`。写 `<VAULT>/resumes/<id>.json`（没有 `resumes` 文件夹就先 `mkdir -p "<VAULT>/resumes"`）：

```json
{
  "schema": 1,
  "id": "jl-yuan-202611",
  "title": "原简历（导入）",
  "target": "",
  "position": "",
  "jd": "",
  "keywords": [],
  "lang": "中文",
  "date": "2026.11",
  "status": "草稿",
  "sent": "",
  "header": {"headline": "<原简历的求职意向，没有就写 \"\">", "photo": false},
  "sections": [
    {"title": "教育经历", "from": "education"},
    {"title": "<原简历的分节名，如 实习经历>", "items": [
      {"card": "<第 3 步的卡片 id>", "writing": "简历条目", "version": "v1 原简历", "text": ""}
    ]}
  ],
  "exports": [],
  "created": "<当前时间>",
  "updated": "<当前时间>"
}
```

- 分节名用原简历的写法（「实习经历」「项目经历」「个人总结」……），顺序和原简历一样，每节里的条目顺序也一样。
- 原简历有照片就把 `photo` 写成 `true`（照片按 `recipes/06-修改删除.md` 存进 `assets/portrait.*`）。
- 查重时并进了已有卡片的条目，`version` 写那次新加的版本名。

写完依次运行：

```bash
python3 -m json.tool "<VAULT>/resumes/<id>.json" > /dev/null && echo OK
```

```bash
python3 "<SKILL>/scripts/resume_model.py" sync "<VAULT>" "<id>"
```

- 期望 `SYNCED <id>`，没有 `BROKEN` 行。
- 有 `BROKEN`：卡片 id 或版本名写错了，改好再 `sync`。

## 第 5 步：对一下页数（可选，有 LaTeX 时）

```bash
mkdir -p /tmp/jingliku-pdf && python3 "<SKILL>/scripts/fill_tex.py" resume "<VAULT>" /tmp/jingliku-pdf/yuan.tex --from "<id>" && cd /tmp/jingliku-pdf && xelatex -interaction=nonstopmode -halt-on-error yuan.tex > /dev/null 2>&1 && grep -o "Output written on yuan.pdf ([0-9]* page" yuan.log
```

页数和原简历差不多就对了。差很多，通常是某段经历漏了或重复了，回头检查第 3 步。

## 第 6 步：告诉用户

一段话说清楚：
- 填了哪些个人信息；
- 拆出了几张卡片（按类型说，如「3 段实习、1 个项目、1 段志愿、1 张技能卡」）；
- 存了一份「原简历（导入）」，在右半屏左栏「简历」里，原文一字没改；
- 有没有和已有卡片合并的。

## 第 7 步：追问（最多 3 个问题）

简历里通常缺「思考」和一部分结果数字。挑最有价值的问，**一行一个问题、每个问题只问一件事**（不要把两件事塞进同一个问题），例如：
- 「字节跳动那段，你觉得最难的一件事是什么？当时怎么想的？」（补 `thought`）
- 「二手书小程序上线后，还有别的数据吗，比如复购或留存？」（补 `result`）
- 第 1、2 步里拿不准的：读不清的字、和已有信息冲突的地方。

用户回答后，按 `recipes/06-修改删除.md` 补进对应卡片。
