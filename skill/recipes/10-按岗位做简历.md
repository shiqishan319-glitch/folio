# 10 按岗位做简历：选经历 → 选版本 → 存成一份简历 → 导出

用户说「帮我做一份投 XX 的简历」「按这个 JD 改简历」「生成简历」时，读这个文件。

**一份简历 = 一张引用清单。** 它记录用哪张卡片的哪个写法版本、按什么顺序放，存在 `<VAULT>/resumes/<id>.json`。文字本身只存在卡片里。

**为什么这样存：** 投过的每份简历都能找回来（投了谁、用了哪几段、哪个版本）；在一份简历里写好的新版本存回了卡片，下一份简历直接能用。

**用户也会在右半屏改简历**（拖动排序、换版本、改字、标记已投递）。所以改简历文件前，先重新读一遍（铁律第 3 条）。

**两种状态：**
- `草稿`：跟着卡片走，卡片里的版本改了，简历自动跟着变。
- `已投递`：内容冻结，以后卡片怎么改都不影响它。要改就复制一份新草稿。

---

## 第 1 步：弄清要求，看看有没有旧简历

从用户的话里找出这几点，找不到的问（一次最多问 3 个）：

- **投什么**：公司 / 项目 + 岗位名
- **岗位要求（JD）**：用户贴了就整段留着，第 5 步存进 `jd`
- **语言**：中文 / 英文（英文简历单独做一份）
- **篇幅**：默认一页
- **照片**：要不要放（默认看个人信息里有没有照片）

看看已有的简历：

```bash
python3 - "<VAULT>" <<'EOF'
import json, glob, os, sys
fs = sorted(glob.glob(os.path.join(sys.argv[1], "resumes", "*.json")))
for f in fs:
    r = json.load(open(f, encoding="utf-8"))
    print(r.get("id"), "|", r.get("title"), "|", r.get("position"), "|", r.get("status"), r.get("sent") or "")
print("RESUMES", len(fs))
EOF
```

- 有同类岗位的旧简历：问用户「在『<旧简历标题>』的基础上改，还是重新做？」。要在旧的上面改，跳到文末「复制一份改投」。
- 输出 `RESUMES 0` 或用户要重新做：继续第 2 步。

## 第 2 步：补齐抬头

```bash
python3 -c "import json;p=json.load(open('<VAULT>/config.json',encoding='utf-8')).get('profile',{});print('NAME', p.get('name') or '空');print('CONTACT', p.get('email') or p.get('phone') or '空');print('EDU', len(p.get('education') or []))"
```

- `NAME 空`、`CONTACT 空`、`EDU 0`：问用户补上（姓名、邮箱或电话、学校 / 专业 / 时间），按 `recipes/06-修改删除.md` 里「修改个人信息」写进 `config.json`。用户说先不填，就跳过。
- 都有：继续。

## 第 3 步：选经历，给用户确认

列出能放进简历的卡片和它们已有的简历版本：

```bash
python3 - "<VAULT>" <<'EOF'
import json, glob, os, sys
for f in sorted(glob.glob(os.path.join(sys.argv[1], "experiences", "*.json"))):
    c = json.load(open(f, encoding="utf-8"))
    if c.get("type") == "思考":
        continue
    vs = [v["name"] for w in c.get("writings", []) if w.get("type") == "简历条目" for v in w.get("versions", [])]
    print(c.get("id"), "|", c.get("type"), "|", c.get("title"), "|", c.get("time", ""), "| 简历版本:", " / ".join(vs) or "无")
EOF
```

对照岗位要求，挑最相关的经历（一页纸通常放 3–6 段），按「和岗位的相关程度」排好，给用户看：

```
这份简历打算放这几段（按相关程度）：
1. 小红书 · 内容运营实习（用「v2 偏数据」）—— JD 要求数据复盘，这段有周报和 30% 的结果
2. 校园公益市集（用「v1 通用」）—— 体现活动策划
3. 技能与语言（用「v2 通用运营向」）
不放：社区博物馆讲解（和岗位关系弱）。可以吗？
```

等用户确认；用户说「不用问我」就直接用你排的。

## 第 4 步：每段选一个版本，没有合适的就写一个新的

- 先从这张卡片已有的「简历条目」版本里挑最贴岗位的。
- **都不合适时**，以最接近的版本为底改写，按 `recipes/04-申请与写法.md` 第 4、5 步的规则**存成卡片的新版本**，名字写成 `v<序号> <岗位方向>`，例如 `v4 内容运营向`。存完校验那张卡片。
- **只用卡片里的事实和数字，不编造。**
- 一个版本里可以有多行：
  - 每行一个要点，能写小标题就写成「小标题：正文」（冒号前不超过 16 个字），导出时小标题会加粗；
  - 想要一句不带圆点的概述，就放在第一行，并且不写小标题。

## 第 5 步：写简历文件

起 id：`jl-<对象拼音缩写>-<岗位拼音缩写>-<年月>`，只用字母、数字、`-`，例如 `jl-xhs-yunying-202611`。检查重名：

```bash
test -e "<VAULT>/resumes/<id>.json" && echo TAKEN || echo FREE
```

`TAKEN` 就在末尾加 `-2`。然后写 `<VAULT>/resumes/<id>.json`（`resumes` 文件夹不存在就先 `mkdir -p "<VAULT>/resumes"`）：

```json
{
  "schema": 1,
  "id": "jl-xhs-yunying-202611",
  "title": "小红书 · 内容运营实习",
  "target": "小红书",
  "position": "内容运营实习生",
  "jd": "用户贴的岗位要求原文；没有就写 \"\"",
  "keywords": ["选题", "数据复盘", "活动策划", "Excel"],
  "lang": "中文",
  "date": "2026.11",
  "status": "草稿",
  "sent": "",
  "header": {"headline": "求职意向：内容运营实习 · 可立即到岗", "photo": true},
  "sections": [
    {"title": "教育经历", "from": "education"},
    {"title": "实习经历", "items": [
      {"card": "xhs", "writing": "简历条目", "version": "v2 偏数据", "text": ""}
    ]},
    {"title": "项目经历", "items": [
      {"card": "fair", "writing": "简历条目", "version": "v1 通用", "text": ""}
    ]},
    {"title": "技能与语言", "items": [
      {"card": "skills", "writing": "简历条目", "version": "v2 通用运营向", "text": ""}
    ]}
  ],
  "exports": [],
  "created": "<当前时间>",
  "updated": "<当前时间>"
}
```

要点：
- **`keywords`**：从岗位要求里挑 5–8 个最关键的词（技能、职责）。右半屏会用它显示「已覆盖 5/7」。没有 JD 就写 `[]`。
- **`sections`**：
  - 分节标题按卡片类型写：实习 → 实习经历，项目 → 项目经历，志愿者 → 志愿经历，获奖 → 荣誉奖项，技能 → 技能与语言。
  - 「教育经历」只写 `"from": "education"`，内容会从个人信息里自动取。
  - 顺序就是简历上的顺序。
- **`version` 要和卡片里的版本名一字不差。** 一张卡片在一份简历里只出现一次。
- **`text` 先留空 `""`**，下一条命令会自动填上（每条的文字快照）。
- `header.headline` 是这份简历的求职意向；`photo` 写 `false` 就不放照片。
- 当前时间：`python3 -c "import datetime;print(datetime.datetime.now().astimezone().isoformat(timespec='seconds'))"`

写完依次运行：

```bash
python3 -m json.tool "<VAULT>/resumes/<id>.json" > /dev/null && echo OK
```

```bash
python3 "<SKILL>/scripts/resume_model.py" sync "<VAULT>" "<id>"
```

- 期望输出 `SYNCED <id>`，没有别的行。
- 出现 `BROKEN <id>: <卡片>/<版本> (no such version ...)`：版本名写错了。用第 3 步的命令看正确的名字，改好 `version`，再运行一次 `sync`。
- 出现 `(no such card)`：卡片 id 写错了，用 `ls "<VAULT>/experiences/"` 查。

## 第 6 步：导出 PDF，检查是不是一页

先按 `recipes/07-导出PDF.md` 第 1 步检查 LaTeX（没有 LaTeX 就跳到本步末尾的「没有 LaTeX」）。然后：

```bash
mkdir -p /tmp/jingliku-pdf && python3 "<SKILL>/scripts/fill_tex.py" resume "<VAULT>" /tmp/jingliku-pdf/resume.tex --from "<id>"
```

```bash
cd /tmp/jingliku-pdf && xelatex -interaction=nonstopmode -halt-on-error resume.tex > /dev/null 2>&1 && grep -o "Output written on resume.pdf ([0-9]* page" resume.log || tail -30 resume.log
```

- 输出 `... (1 page`：正好一页，继续。
- 输出 `(2 page` 或更多：超了。**按这个顺序压**，每做一次就重新导出、再看页数：
  1. 换成同一张卡片里更短的版本（改 `version`，再 `sync`）；
  2. 问用户删掉哪一段（从和岗位最不相关的开始建议）；
  3. 最后才动版式：编辑 `/tmp/jingliku-pdf/resume.tex` 开头的字号或页边距，只影响这一次。
- 打印了日志：按 `recipes/09-踩坑与解决.md` 的「LaTeX」部分处理。

放到用户要的位置（没说就放「下载」），同时在数据目录里留一份存档：

```bash
cp /tmp/jingliku-pdf/resume.pdf "$HOME/Downloads/<简历标题>.pdf" && cp /tmp/jingliku-pdf/resume.pdf "<VAULT>/resumes/<id>.pdf" && echo SAVED
```

再读一遍 `<VAULT>/resumes/<id>.json`，在 `exports` 里加一条，然后校验：

```json
"exports": [{"file": "resumes/<id>.pdf", "date": "<当前时间>"}]
```

**没有 LaTeX：** 用网页打印版，版式一样：

```bash
python3 "<SKILL>/scripts/fill_html.py" resume "<VAULT>" "$HOME/Downloads/<简历标题>.html" --from "<id>"
```

告诉用户用浏览器打开它，点「打印 / 存为 PDF」。网页运行时也可以直接打开 `<网页地址>/resume-print?resume=<id>`。

## 第 7 步：告诉用户

一段话说清楚这几件事：
- 用了哪几段经历、各用的哪个版本；
- 新存了哪些版本（存在哪张卡片下）；
- 一共几页；PDF 存在哪里。

再提醒一句：「右半屏左栏『简历』里能看到这份，可以直接拖动调整顺序、换版本、改字，改动会存回卡片。」

最后问一句：「投出去了吗？投了告诉我，我把这份标记为已投递（之后卡片再改也不会影响它）。」

## 用户说「投了」：标记为已投递

```bash
python3 "<SKILL>/scripts/resume_model.py" sync "<VAULT>" "<id>" --sent
```

- 期望输出 `SENT <id> <日期>`。这会把每条的文字冻结成当前版本，并记下投递日期。
- 输出 `SKIPPED ... already sent`：早就标记过了，不用再做。

## 复制一份改投

1. 读旧简历，整份复制成新文件。新 id 按第 5 步起名，`title`、`target`、`position`、`jd`、`keywords` 换成新岗位的。
2. 新文件里的 `status` 改回 `"草稿"`，`sent` 改成 `""`，`exports` 改成 `[]`，`created` / `updated` 写当前时间。
3. 按第 3、4 步调整经历和版本，然后从第 5 步的「写完依次运行」继续。

## 用户想改简历里的某一句

**改的是卡片里的版本，不是简历文件。** 先问一句：「覆盖原来的『<版本名>』，还是另存一个新版本？」
- **覆盖**：改那张卡片里这个版本的 `text`。注意别的简历也可能用着它：用 `grep -l "<版本名>" "<VAULT>/resumes/"*.json` 看一眼，告诉用户会影响哪几份草稿（已投递的不受影响）。
- **另存**：按 04 第 5 步在卡片里新加一个版本，再把简历里这一条的 `version` 改成新名字。

两种情况改完都运行一次 `sync`（命令见第 5 步）。已投递的简历不能改：先「复制一份改投」。

## 检查所有简历的引用

卡片改了版本名、删了版本或卡片之后，运行：

```bash
python3 "<SKILL>/scripts/resume_model.py" check "<VAULT>"
```

每份简历一行：`OK <id>`，或 `BROKEN <id>: <卡片>/<版本> (...)`。`BROKEN` 的那份按第 5 步的说明修好 `version`，再 `sync`。已投递的简历保留着快照，可以不修。
