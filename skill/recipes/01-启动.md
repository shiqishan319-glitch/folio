# 01 启动（每次会话第一次用经历库时做一遍）

把下面命令里的 `<SKILL>`、`<VAULT>` 换成真实的绝对路径（见 SKILL.md「两个路径」）。按顺序做，每步看「期望结果」，不对就按「如果失败」处理。

---

## 第 1 步：检查 Python

```bash
python3 --version
```

- 期望结果：`Python 3.9` 或更高（例如 `Python 3.12.4`）。
- 如果失败（提示找不到命令，或版本低于 3.9）：告诉用户「经历库需要 Python 3.9 以上，要我帮你安装吗？」用户同意后再装（macOS：`brew install python`；或去 python.org 下载）。用户不同意就停下。

## 第 2 步：确认数据目录存在

```bash
test -f "<VAULT>/config.json" && echo EXISTS || echo MISSING
```

- 输出 `EXISTS`：跳到第 3 步。
- 输出 `MISSING`：问用户一句：「经历库的数据默认放在 `<VAULT>`，可以吗？要不要先放几条示例数据看看效果？」然后：

**用户只要空的数据目录：**
```bash
mkdir -p "<VAULT>/experiences" "<VAULT>/applications" "<VAULT>/assets" "<VAULT>/.trash" && cp "<SKILL>/examples/empty-config.json" "<VAULT>/config.json" && echo DONE
```

**用户想先看示例：**
```bash
mkdir -p "<VAULT>/assets" "<VAULT>/.trash" && cp -R "<SKILL>/examples/sample-vault/." "<VAULT>/" && echo DONE
```
（告诉用户：示例都是虚构的，以后说「删掉示例数据」即可清掉，见 `recipes/06-修改删除.md`。）

- 期望结果：输出 `DONE`。

## 第 3 步：确保网页在运行（这一条命令就够）

```bash
python3 "<SKILL>/scripts/serve.py" --vault "<VAULT>" --ensure
```

它会自己判断：已经在运行就直接告诉你地址；没在运行就在后台启动（这条命令结束后也会一直运行下去），再告诉你地址。

| 输出 | 意思 | 下一步 |
|---|---|---|
| `RUNNING http://127.0.0.1:XXXX/` | 本来就在运行 | 记下地址，做第 4 步 |
| `STARTED http://127.0.0.1:XXXX/` | 刚启动好 | 记下地址，做第 4 步 |
| `NO_VAULT ...` | 数据目录不存在 | 回到第 2 步 |
| `FAILED ...` | 启动失败 | 看日志 `cat "<VAULT>/.serve.log"`，按 `recipes/09-踩坑与解决.md` 处理 |

**为什么网页要一直开着：** 用户在右半屏看到的、改的，都要靠它读写数据。它停了，网页就会显示「连接中断」，用户的修改也存不下来。所以：
- **每次处理用户的请求之前，都先运行一遍这条命令。** 它很快，已经在运行时什么也不改。
- **不要主动关掉它**，会话结束时也不要。下次用的时候它还在，或者用这条命令重新拉起来。
- 重启是安全的：地址（端口）和写入口令都会沿用上一次的，用户已经打开的网页会在几秒内自己接上，不用刷新。

## 第 4 步：在右半屏打开网页

- **Claude Code 桌面版：** 用内置浏览器（预览面板）打开第 3 步得到的地址。
- **其他工具：** 如果你有打开网页的能力（内置浏览器、预览、canvas），就用它打开这个地址。
- **没有这种能力：** 把地址告诉用户：「请在浏览器里打开 http://127.0.0.1:XXXX/ ，经历库会显示在那里。」

## 完成

对用户说一句：「经历库已经打开（地址 http://127.0.0.1:XXXX/）。你可以把素材发给我，或者告诉我你要申请什么。」然后回到 SKILL.md 的任务表，处理用户的请求。
