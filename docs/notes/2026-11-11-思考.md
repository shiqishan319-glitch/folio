## 痛点

是找不到？还是只是很乱，难以一起提取？

把相关材料一股脑给到 AI，传给 GitHub 或者 AI 在本地开始整理和维护一个结构化数据库。

核心痛点不在"找不到"，而在每次都要重新归纳。你能一下子想起有哪些经历，说明检索没问题。真正费时间的是三件事：

1. 素材散：证书在相册，策划案在网盘，数据在微信聊天记录里
2. 当时没记关键信息：事后想写"带来了什么结果"，数字已经想不起来了
3. 每次申请的写法不一样：同一段经历，申志愿者要突出动机，申奖学金要突出成果，填表要压到 150 字，每次都得重写

## 场景

所以：

1. 有一个记录信息库的习惯
2. 在录入的时候就提醒你补充哪些维度，你也可以不补充，就先帮我结构化地留档
3. 方便提取
4. 最好能存各种形态的，比如我做了一个策划案，有视频，有 ppt，有图片，有 pdf，但是这个先不作为 P0 需求。

其他需求：适配 Codex、WorkBuddy、豆包办公、千问办公。用啥最多搞一下适配。

产品价值：产品形态从 APP → 微信支付宝小程序 → 长在 Codex 里。
上一代依托于个人信息（微信实名制）、传播渠道（好友）、付款方式，这些就是小程序的基础建设。
对于下一个时代的 app 的预期，其实是长在 Codex 里或者能适配每个人现在常用软件。
