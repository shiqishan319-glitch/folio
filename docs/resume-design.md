## 一、为什么现在做简历

简历是用户最常用的产出，也最直接对应 PRD 的核心痛点：**同一段经历有很多种写法，版本散在各个申请文件里**。投 10 个岗位就有 10 份略有不同的简历：选哪几段经历、用哪个版本、什么顺序，每份都不一样，事后也找不回来。

经历库已经把「写法」做成了卡片下的多版本，差的是最后一环：**一份简历本身没有被存下来**。

## 二、现在有什么，缺什么

**已有：**

- `fill_tex.py resume` / `fill_html.py resume`：从卡片拼简历，LaTeX 版和网页打印版两种。
  - `--prefer` 按版本名里的关键词选版本，`--ids` 指定放哪几段、按什么顺序。
  - 教育背景、技能、证件照来自 `config.json` 的 `profile`。
- 前端：左栏「打印版简历」（全部经历）和申请信里的「关联经历打印版」，都在新标签页打开 `/resume-print`。

**缺：**

| # | 缺口 | 后果 |
|---|---|---|
| 1 | 简历每次临时拼，不存 | 投某岗位用了哪几段、哪个版本、什么顺序，事后找不回；没法「复制上一份改改再投」 |
| 2 | 左栏「简历」里放的其实是自荐信 / 动机信 | 真正的简历一来，名字就冲突了 |
| 3 | 右半屏里看不到、也改不了简历 | 调顺序、换版本都要回到对话里说，再重新导出 |
| 4 | 不检查页数 | 超过一页也不提醒 |
| 5 | 没有「按岗位定制」的完整菜谱 | 现有菜谱只教改写单段经历（04），小模型拼不出一份完整简历 |
| 6 | 没有「从旧简历导入」 | 大多数人手里已有一份旧简历，这本该是最自然的第一次使用 |

## 三、核心设计：简历是一份「引用清单」

**一份简历 = 按顺序列出「用哪张卡片的哪个版本」，加上这份简历自己的抬头和分节。**

条目引用卡片里的写法版本，文字本身始终只住在卡片里。原因：

- **写法只有一份来源。** 在某份简历里把一句话改好，等于给那张卡片存了一个新版本，其他简历和申请信都能复用。这正是「生成结果存回库里」的理念。
- **卡片改进了，草稿简历自动跟着变好。**

但**已经投出去的简历不能跟着变**，否则就不知道当初投的是什么。所以每条也存一份文字快照，按状态决定用哪个：

| 状态 | 显示和导出用哪个文字 | 什么时候变成这个状态 |
|---|---|---|
| `草稿` | 卡片里那个版本的**当前文字**，同时把快照刷新成它 | 新建时 |
| `已投递` | **快照**，卡片之后再改也不影响 | 用户说「投了」，或 AI 导出最终版后问用户、用户确认时 |

快照还兼作兜底：引用的版本被改名或删除时，仍然能显示出原来的文字，并提示「原版本已不在」。

### 存在哪里：新目录 `resumes/`（推荐）

```
~/folio/
├── experiences/    一段经历一张卡片（不变）
├── applications/   自荐信、动机信、个人陈述（不变；前端左栏改叫「申请信」）
└── resumes/        简历，一份一个文件（新增）
```

- **为什么不放进 `applications/` 加一个 `kind: "简历"`：** 两者形状不同（申请信是一段段正文，简历是分节的条目引用）。放在一起，AI 和前端都要先判断类型再处理，小模型容易写混；旧版前端读到简历格式的文件也可能出错。
- **代价很小：** `serve.py` 的写入白名单 `WRITABLE` 加一项 `"resumes/"`；前端多轮询一个目录。

### `resumes/<id>.json` 格式

```json
{
  "schema": 1,
  "id": "jl-xhs-yunying-202611",
  "title": "小红书 · 内容运营实习",
  "target": "小红书",
  "position": "内容运营实习生",
  "jd": "（可选）岗位描述原文，AI 选经历时用",
  "keywords": ["选题", "数据复盘", "活动", "用户增长", "Excel", "SQL"],
  "lang": "中文",
  "date": "2026.11",
  "status": "草稿",
  "sent": "",
  "header": {"headline": "求职意向：内容运营实习 · 可立即到岗", "photo": true},
  "sections": [
    {"title": "教育背景", "from": "education"},
    {"title": "实习经历", "items": [
      {"card": "xhs", "writing": "简历条目", "version": "v2 偏数据",
       "text": "搭建话题数据复盘表，按周跟踪 5 项指标并输出选题建议，推动话题周均互动量提升约 30%。"},
      {"card": "ali", "writing": "简历条目", "version": "v1 通用", "text": "……"}
    ]},
    {"title": "项目经历", "items": [ … ]},
    {"title": "技能与语言", "items": [
      {"card": "skills", "writing": "简历条目", "version": "v2 通用运营向", "text": "……"}
    ]}
  ],
  "exports": [{"file": "resumes/jl-xhs-yunying-202611.pdf", "date": "2026-11-22T20:00:00+08:00"}],
  "created": "2026-11-22T20:00:00+08:00",
  "updated": "2026-11-22T20:00:00+08:00"
}
```

| 字段 | 说明 |
|---|---|
| `title`, `target`, `position`, `lang`, `date` | 打标维度，用于检索和「找上次投同类岗位那份」 |
| `jd` | 可选。存下岗位要求，之后改这份简历时 AI 不用再问 |
| `keywords` | 可选。AI 从 JD 里提炼的 5–8 个关键词；前端用来显示「已覆盖 5/7」、给经历按相关度排序 |
| `status`, `sent` | `草稿` / `已投递`；`sent` 是投递日期 |
| `header` | 只覆盖这份简历的抬头（求职意向、要不要放照片）；姓名、联系方式、教育仍来自 `config.json` 的 `profile` |
| `sections[].from` | 特殊分节，目前只有 `education`（从 `profile.education` 渲染） |
| `sections[].items[]` | `card` + `writing` + `version` 指向卡片里的一个版本，`text` 是快照。条目的标题行（机构 · 角色、时间）从卡片的 `org` / `role` / `time` 取，不在这里重复 |
| `exports` | 导出过的 PDF。PDF 很小，直接存档为 `resumes/<id>.pdf`（和 JSON 放在一起），留档「当初投的是什么」 |

**几条规则（写进 data-format.md）：**

- 版本用**名字**引用（不新加版本 id，保持格式简单，小模型不用生成随机 id）。代价是：改名或删除版本时，要同步改引用它的简历。前端改名时自动改；AI 按 06 菜谱改。快照保证即使漏改也不会丢字。
- 分节标题自由写。默认按卡片类型生成（实习 → 实习经历，项目 → 项目经历……）。
- 一张卡片在一份简历里只出现一次。
- 不允许没有 `card` 的条目：所有文字都必须有卡片来源。要写的东西不在库里，就先入库。
- 英文简历是**另一份**简历（`lang: "英文"`），引用卡片的英文版本，不在同一份里做语言切换。

## 四、AI 侧：新菜谱 `10-按岗位做简历.md`

照现有菜谱的写法：每步有可复制的命令、期望输出、失败分支。

1. **弄清要求：** 岗位或 JD、语言、篇幅（默认一页）、要不要照片。用户贴了 JD 就存进 `jd`。有同类岗位的旧简历（`resumes/` 里 `position` 相近）时，问「在上次那份基础上改，还是重新做？」
2. **补齐抬头：** 读 `profile`；缺姓名、联系方式、教育背景时最多问 3 个问题（沿用 07 菜谱现有规则）。
3. **选经历：** 列出所有可放进简历的卡片（`resume_types`），对照 JD 给出建议清单：放哪几段、什么顺序、每段一句理由。等用户确认（「不用问我」时直接用）。
4. **选版本：** 每段从已有版本里挑最贴岗位的一个。都不合适时，以最接近的版本为底改写，**存成卡片的新版本**（`v<N> <岗位方向>`），再引用它。只用卡片里的事实和数字。
5. **写 `resumes/<id>.json` 并校验：** id 规则 `jl-<对象缩写>-<岗位缩写>-<年月>`。用脚本检查所有引用都存在（见第六节）。
6. **导出并检查页数：** 走 07 菜谱的 LaTeX 路径。编译后从日志读页数；超过要求的页数时，按顺序：换成同一卡片里更短的版本 → 让用户选删哪段 → 最后才缩字号或页边距。
7. **汇报：** 用了哪些经历、哪个版本；新存了哪些版本；页数；PDF 位置。然后问一句「投出去了吗？投了我把这份标记为已投递」。

另外两条小流程，写在同一个菜谱里：

- **复制改投：** 复制一份已有简历，改 `target` / `position`，状态回到 `草稿`，再按第 3、4 步调整。
- **改简历里的一句话：** 用户在对话里说「把第二条改成……」时，改的是卡片的版本：问一句「覆盖原版本，还是另存为新版本？」（另存时简历改为引用新版本）。

现有菜谱需要跟着改：

- **06 修改删除：** 改名或删除写法版本前，先 `grep` 一下 `resumes/` 里有没有引用；有就同步改。
- **07 导出 PDF：** 简历导出加 `--from <简历id>`；无参数时保持现状（全部经历），作为「快速看一眼」的兜底。

## 分工：前端做什么，agent 做什么

**原则：确定的、要马上看到结果的操作归前端；要判断、要写新文字、要用本机环境的事归 agent。** agent 那一侧由用户自己的 AI 工具照菜谱去做（`recipes/10-按岗位做简历.md`），我们的重点是把前端做好。前端遇到 agent 的活，只放一个「问 AI」按钮：复制一句写好的指令，用户粘贴到左边对话。前端不调用任何模型。

| 事情 | 前端（右半屏） | agent（左边对话） |
|---|---|---|
| 看简历、切换简历 | ✓ 左栏「简历」列表，一页 A4 预览 | |
| 新建 | ✓ 空白简历、复制一份改投 | ✓ 按 JD 从零做一份（挑经历、排顺序） |
| 加 / 删 / 排一段经历 | ✓ 拖卡片到纸上、「添加经历」、拖动或 ⌥↑↓ 排序、✕ 移除（可撤销） | |
| 每段用哪个版本 | ✓ 在已有版本之间切换（看得到字数、哪些简历也在用） | ✓ 没有合适的就写一个新版本 |
| 改一句话 | ✓ 双击就地改，存回卡片：覆盖 / 另存为新版本 | ✓ 按岗位改写、润色 |
| 求职意向、照片、分节名、标题 | ✓ 就地改 | |
| 岗位关键词 | ✓ 增删、看覆盖情况、点词定位 | ✓ 从 JD 里提炼 |
| 一页纸 | ✓ 实时显示「还剩 N 行 / 超出 N 行」，一键换更短的版本、移除最不相关的一段 | ✓ 改写成更短的版本 |
| 导出 | ✓ 打印版（`/resume-print`，浏览器存 PDF） | ✓ LaTeX 精排 PDF |
| 投递 | ✓ 标记已投递（冻结）、复制为新草稿 | ✓ 用户说「投了」时 `sync --sent` |
| 引用断了 | ✓ 标红「原版本不在了 / 卡片已删除」，仍显示快照；版本改名时自动改引用 | ✓ `resume_model.py check` 后修复 |

## 五、前端侧：在纸上直接改

> 可点击的原型：[`demo/resume-editor.html`](../demo/resume-editor.html)（静态，示例数据，不保存）。截图：`demo/screenshots/简历编辑器-全屏.jpg`、`简历编辑器-半屏.jpg`。
> 打开方式：`python3 -m http.server 8765 --bind 127.0.0.1 --directory demo`，然后访问 <http://127.0.0.1:8765/resume-editor.html>。

### 三条原则

1. **只有一张纸，在纸上改。** 不另做一棵「大纲树」再配预览：A4 页面本身就是编辑器，所见即所得。悬停某一条，就在它上方浮出小工具条。
2. **改的永远是卡片。** 换版本、改文字、AI 改写，最后都落到卡片的写法版本上，简历只记引用。界面每次都把这一点说出来（「这段改动存回『小红书』卡片：覆盖 / 另存为」）。
3. **左边就是 AI。** 产品住在 AI 工具的右半屏，重活交给左边的对话。界面里凡是 AI 擅长的事（按 JD 生成、改写一条、压到一页），都做成「问 AI」按钮：点了复制一句写好的指令，用户粘贴到左边就行。前端不调用任何模型，也不需要 API key。

### 布局（宽屏 ≥ 1100）

```

│            │ 🔍 搜索       ├───────────────────────────────────────────────┤
│ 简历    ＋  │ 按岗位相关|时间│ 岗位要求  ✓选题 ✓数据复盘 ✓活动 ◌用户增长 …   已覆盖 5/7  看原文 │
│ ● 某内容平台│ ┌──────────┐ ├───────────────────────────────────────────────┤
│ ● 某 AI 公司│ │实习 小红书 │ │  ┌──────────────── A4 ────────────────┐      │
│            │ │✓ 已在简历中│ │  │ 示例同学                     [照片] │      │
│ 申请信  ＋  │ └──────────┘ │  │ 教育经历 ─────────────────────────  │      │
│ 某支教·自荐信│ ┌──────────┐ │  │ 实习经历 ─────────────────────────  │      │
│ 某公益·动机信│ │志愿者 博物馆│ │  │  小红书 - 运营实习生    [v2 偏数据▾ ✎ ✕]│   │

```

- **左栏：** 「简历」和「申请信」两组，各自有「＋」。简历前面的圆点：黄色是草稿，绿色是已投递（带投递日期）。
- **中栏「经历素材」：** 就是经历卡片，可以直接拖到纸上，或点「＋」加入。
  - 默认「按岗位相关」排序，卡片上标出它命中的 JD 关键词。
  - 已在简历里的卡片变淡、标「✓ 已在简历中」，点它会滚到纸上那一条并闪一下。
  - 「思考」类卡片不出现。
- **右边工作区：** 顶栏、岗位要求条、纸。

### 纸上的交互

| 操作 | 怎么做 | 结果 |
|---|---|---|
| 加一段经历 | 从中栏拖到纸上，或点卡片上的「＋」 | 自动进入该类型的分节（实习 → 实习经历），没有就新建分节（放在技能之前）；拖动时目标分节高亮，蓝线标出插入位置；新加的一条闪一下 |
| 调顺序 | 拖动条目；分节用标题上的 ↑ ↓ | 同一分节内重排 |
| 换版本 | 悬停 → 工具条上的版本名 ▾ | 弹出这张卡片的所有「简历条目」版本：名字、字数、前三行预览；底部「让 AI 针对这个岗位写一个新版本」 |
| 改文字 | 双击正文，或工具条「✎ 改」 | 离开时出现「这段改动存回『小红书』卡片：覆盖『v2 偏数据』 / 另存为『v4 内容运营向』 / 撤销」；改完的文字先显示在纸上 |
| 移除 | 工具条「✕」 | 只从这份简历拿掉，卡片不受影响；提示条里有「撤销」 |
| 改分节名 | 悬停分节标题 →「改名」 | — |
| 改抬头 | 直接点「求职意向」那一行改；照片右上角悬停「不放照片」，没照片时有「＋ 照片」 | 只改这份简历的 `header`，姓名和联系方式仍来自个人信息 |
| 键盘 | 点一条选中：↑ ↓ 切换，⌥↑ ⌥↓ 调顺序，Enter 改，Delete 移除，Esc 取消 | — |
| 撤销 | ⌘Z / ⇧⌘Z，或顶栏的 ↶ ↷ | 所有改动都能撤销（含卡片版本的覆盖和另存）；改一次标题算一步 |

### 篇幅：始终知道还剩多少

- 顶栏的篇幅条：「还剩 31 行」；剩不到 4 行变黄；超出变红，显示「超出 13 行 ›」，纸上同时出现红色虚线「第 1 页到此为止」。
- **点篇幅条 = 压回一页的建议：**
  - 每条能换成同一卡片里更短的版本时，列出「小红书 换成『v1 通用』 省 662 字」，点一下就换；
  - 和 JD 最不相关的一条（命中关键词最少）可以一键移除（可撤销）；
  - 最后是「让 AI 帮我改到正好一页」。

### 岗位要求条

- AI 做简历时从 JD 里提炼 5–8 个关键词，存进简历记录的 `keywords`。前端只做字符串匹配：纸上的文字里出现了就打 ✓。
- 点已覆盖的词：在纸上用黄色标出包含它的条目。点没覆盖的词：中栏筛出含这个词的经历；库里没有，就提示可以让 AI 追问补一段。
- 关键词可以自己增删：悬停出现 ×，末尾有「＋」。
- 「看原文」展开存下的 JD 全文。

### 版本复用看得见

版本列表里，每个版本下面写着「也用在：某 AI 公司 · 产品实习（已投递）」。改写或覆盖一个版本前，用户就知道会影响哪些简历（已投递的不受影响）。

### 保存与导出

- 顶栏有「● 已保存」：每次改动后短暂显示「保存中…」。正式实现里每次改动就是一次 `PUT resumes/<id>.json`，没有「保存」按钮。
- 「导出 PDF」是两个选项：
  - **精排 PDF（推荐）**：复制指令，让左边的 AI 用 LaTeX 模板导出，和纸同一版式；
  - **浏览器打印**：马上就能存，字体随系统。

### 状态

- **草稿 / 已投递** 是顶栏的一个切换。切到已投递时，当前每条的文字存成快照，记下日期。
- 已投递的简历：顶部一条绿色说明「11-20 投给某 AI 公司的版本，内容已冻结；之后卡片怎么改都不影响它」，纸上没有工具条，中栏不能加；要改就点「复制为新草稿」。

### 新建

左栏「＋」弹出三项，推荐的放第一：
1. **让 AI 按岗位要求生成**（复制指令：贴上 JD，AI 挑经历、选版本、排到一页）；
2. **复制当前这份**（改投相似岗位时最快）；
3. **空白简历**：纸上出现引导「从左边把经历拖进来，或者让 AI 按岗位要求先排一版」。

### 半屏（< 1100，AI 工具右半屏最常见的宽度）

- 左栏收进顶栏最左边的「≡」：点开是简历列表 + 新建。
- 中栏变成从左侧滑出的抽屉，由顶栏「＋ 添加经历」打开；开始拖卡片时抽屉自动收起，露出纸。
- 顶栏固定两行：第一行「≡ · 标题 · 导出 PDF」，第二行「状态 · 篇幅 · 添加经历 · 问 AI」。
- 纸按宽度等比缩小，交互不变。

### 和其他部分的衔接

- **预览和导出同一版式。** 纸的样式、`templates/html/resume.html`（网页打印版）和 `templates/latex/resume.tex`（LaTeX）三者保持一致：无衬线、分节标题加粗 + 通栏细线、条目「机构 - 角色」右侧时间、要点加粗小标题、首行概述不带圆点。LaTeX 模板已按 sqs 的简历改好（`demo/screenshots/简历模板-LaTeX.jpg`）；网页打印版要在第 2 步跟着改。
- **渲染规则（三处共用）：**
  - 一个版本的文字按行拆。
  - 「小标题：正文」（冒号前 1–16 个字）渲染成加粗小标题。
  - 如果其他行都有小标题，而第一行没有，第一行就是这一条的概述，不加圆点。
- **经历卡片上：** 「申请引用」旁边加「简历引用 N」，点开列出用到它的简历。
- **改写法版本名时：** 前端顺手更新所有引用它的简历文件。

### 正式前端里新增的（v0.3.10）

- **专注模式**：收起时间线和左栏，纸占满宽度；半屏时自动进入，用户切换后以用户为准。加经历改用「添加经历」弹层。
- **缩放**：顶栏显示当前比例，点一下在「适应宽度」和「100%」之间切换（100% 时纸可横向滚动）。
- **撤销 / 重做**：⌘Z / ⇧⌘Z 和 ↶ ↷；AI 从外部改了文件时清空历史。
- **改回草稿要确认**，推荐改用「复制为新草稿」。
- **经历详情的「简历引用」**和 `#res=<id>` 深链接。

原型里没做的三项已在 v0.3.11 补上：分节拖拽、对照另一份简历（中英文并排）、刷新后保留撤销历史。首次打开另有分区引导。

## 八、测试用例 `resume-for-jd`

给 sample-vault 一段内容运营岗位的 JD，要求做一份一页中文简历并导出 PDF，不用确认。检查项：

1. `resumes/` 下新增一份，JSON 合法，`status` 是 `草稿`。
2. 所有条目的 `card` / `writing` / `version` 都能在卡片里找到，`text` 与该版本文字一致。
3. 包含小红书那段（与 JD 最相关），不包含「思考」类型的卡片。
4. 新写的版本存回了卡片（若有），原有版本一字未改。
5. 条目文字里的数字都能在对应卡片里找到（不编造）。
6. `outputs/` 里有 PDF，且只有 1 页。
